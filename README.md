# Muhammad — 6.6.1

RFP 요구사항 관리, 원문 열람, 프로젝트 공동 작업을 위한 웹 앱입니다.

## 현재 반영된 화면

6.6.1: 전체 목록 관리자로 접속하면 프로젝트를 비밀번호 재입력 없이 열고 삭제할 수 있습니다. 삭제는 이름 입력 없이 최종 확인을 거치고 프로젝트 폴더와 첨부 자료를 함께 휴지통으로 이동합니다. 일반 공유 사용자는 기존 프로젝트별 비밀번호와 권한을 유지합니다.

로그인·비밀번호 변경·접속 기억 설정에서 ‘이 기기에서 관리자 접속 기억 (90일)’을 선택할 수 있습니다. 비밀번호나 비밀번호 검증값은 저장하지 않고 서버가 발급한 접속 토큰만 보관합니다. 선택하지 않으면 탭 세션에만 12시간 유지합니다. ‘목록 잠금’은 기억된 접속도 지우고, 관리자 비밀번호 변경은 모든 이전 관리자 토큰과 그 토큰으로 연 프로젝트 접근을 무효화합니다.


- 첫 화면과 `[프로젝트]`의 **관리자로 접속**에서 목록 관리자 비밀번호를 입력하면 Drive에 저장된 전체 프로젝트를 볼 수 있습니다. 목록은 브라우저 접속 기록이 아니라 저장소에서 불러오며, 다른 PC에서도 동일합니다. 각 프로젝트의 접속·편집 비밀번호는 별도로 유지됩니다. 최초 설정은 [저장소 설정 안내](cloud/설정안내.md)를 따릅니다.
- 목록 관리자 인증은 기억하기를 선택하지 않으면 탭 세션에 보관하며 12시간 뒤 만료됩니다. 목록 잠금과 비밀번호 변경을 지원합니다. 로그인 전에는 전체 목록이 표시되지 않습니다.
- 문서함의 AI 요구사항 추출과 사업정보는 **RFP 통합 분석 결과**를 함께 사용합니다. 문서별 한 번의 구간 분석에서 요구사항 후보와 사업정보를 함께 생성합니다. 완료 결과와 중간 진행을 저장하며 다른 메뉴·PC에서는 저장된 결과를 AI 호출 없이 불러옵니다. 새 분석을 명시적으로 시작할 때만 다시 호출합니다. 규칙 기반 추출은 계속 AI를 사용하지 않습니다.
- 프로젝트 AI 질문 히스토리에서 작성자 또는 프로젝트 관리자가 개별·선택 삭제할 수 있습니다. 계정 로그인 없는 구조이므로 작성자는 질문을 만든 브라우저로 확인하며, 작성자 정보가 없는 과거 공유 질문은 프로젝트 관리자만 삭제합니다.
- 목록과 상세 화면 사이 경계선을 드래그하여 너비를 조절합니다. 키보드 방향키도 지원하며 두 번 클릭하면 기본 너비로 돌아옵니다. 같은 브라우저에서 비율을 유지하고 작은 화면에서는 기존 단일 화면 보기를 사용합니다.
- 같은 원본의 동시·반복 다운로드를 합치고, 최대 32MB·3개 파일만 메모리에 재사용합니다. 통합 분석에서도 중복 파싱과 AI 요청을 합치며 완료된 구간은 다시 호출하지 않습니다.

6.6.0 검증: 자동 검사 213개 통과. 시험용 프로젝트로 관리자 목록 잠금·로그인·프로젝트 선택, AI 연결 없이 두 메뉴에서 동일 분석 결과 열람, 질문 삭제, 경계선 드래그·키보드 조절·새로고침 후 너비 복원을 확인했습니다. 모의 요청 검사에서 같은 원본의 동시·반복 다운로드는 1회, 동일 분석 구간을 두 메뉴에서 요청해도 AI 호출은 1회였습니다. 실제 사용자 프로젝트의 삭제·내용 변경이나 유료 AI 호출은 검사에 사용하지 않았습니다.

## 이전 변경 기록

- 공유 프로젝트 목록에 `이름 변경`을 추가했습니다. 현재 프로젝트에 관리자 권한으로 접속했다면 이름만 입력하며, 다른 프로젝트는 해당 관리자용 비밀번호를 확인합니다. 변경된 이름은 목록·상단 제목·공유 화면에 반영됩니다. 프로젝트 ID, 공유 URL, 첨부 파일과 작성 내용은 유지합니다.

6.5.5 검증: 자동 검사 141개 통과. 관리자 권한, 공백·길이 검증, 취소·실패 시 이름 보존, 변경 후 재접속·조회 반영, 다른 프로젝트 이름 수정 시 현재 접속 유지, 동일 URL 및 기존 자료 보존을 확인했습니다.

- 프로젝트 접속·생성 중에는 처리 단계와 경과 시간이 표시됩니다. 화면 구성이 끝나거나 오류가 발생하면 대기 화면을 닫습니다.
- 시작 화면과 `[프로젝트]` 목록에서 공유 링크 복사와 삭제가 가능합니다. 삭제는 관리자용 비밀번호와 정확한 프로젝트 이름을 확인하고, 해당 프로젝트 폴더만 Google Drive 휴지통으로 이동합니다.
- 모달·레이어는 바깥 클릭이나 Esc로 닫히지 않습니다. X 버튼으로 닫으며 저장·확인·취소 등 명시적인 작업 버튼은 기존 동작을 유지합니다.

6.5.4 검증: 자동 검사 134개 통과. 지연 응답 중 로딩 표시, 접속 실패 후 복귀, 공유 링크 복사, 삭제 취소·권한 검사·이름 확인·실패 시 목록 보존·다른 프로젝트 보존을 검사했습니다. 시험용 브라우저 화면에서 로딩, 목록별 공유·삭제, 바깥 클릭·Esc 후 모달 유지와 X 닫기를 확인했습니다. 실제 사용자 프로젝트에 대한 삭제나 AI 호출은 하지 않았습니다.

- 공유 모드의 첫 화면에서 기존 프로젝트 목록을 먼저 보여 줍니다. 프로젝트를 선택한 뒤 비밀번호를 입력하며, 취소하면 목록으로 돌아옵니다. 새 프로젝트는 버튼을 직접 누른 경우에만 만듭니다.
- 로컬 프로젝트 생성·백업 가져오기 한도를 3개에서 10개로 늘렸습니다. 기존 저장소 이름·프로젝트 ID·저장 데이터는 그대로 사용합니다. 공유 프로젝트에는 별도 개수 제한이 없습니다.
- 목록은 이 브라우저의 접속 기록 기준입니다. 다른 브라우저에서 사용한 프로젝트나 목록에 없는 과거 프로젝트는 기존 공유 링크로 접속하면 추가됩니다.

6.5.3 검증: 자동 검사 125개 통과. 프로젝트 선택 전 비밀번호·생성 화면이 열리지 않는지, 접속·생성 취소 후 목록 복귀, 비밀번호 재시도를 확인했습니다. 기존 3개 보존 후 4번째 생성, 9개 보존 후 10번째 생성, 11번째 생성 차단을 검사했습니다. 실제 앱에서도 목록 → 생성 화면 → 목록 복귀를 확인했습니다. 저장소 초기화·이전 작업은 없으며 실제 사용자 프로젝트는 변경하지 않았습니다.

- 미저장 변경 안내에 ‘저장하고 이동’을 추가했습니다. 저장 완료를 확인한 뒤 이동하며, 실패 시 작성 내용을 유지합니다.
- 플래그·AI 설명 저장 후 상세 편집창에 남는 이전 버전을 안전하게 병합하고, 늦게 도착한 조회 응답으로 저장 상태가 되돌아가지 않게 했습니다. 동일 필드의 실제 충돌은 덮어쓰지 않습니다.
- `[프로젝트]`에서 이 브라우저로 생성·접속한 공유 프로젝트를 선택할 수 있습니다. 다른 프로젝트는 해당 비밀번호로 접속하며, 과거 프로젝트는 공유 링크로 한 번 열면 목록에 기록됩니다. 목록에는 이름·ID·저장일만 기록하며 비밀번호와 접속 토큰은 포함하지 않습니다.

6.5.2 검증: 자동 검사 114개 통과. 시험용 브라우저 프로젝트로 저장 후 이동, 실패 시 초안 보존, 자동 저장 이후 상세 저장, 프로젝트 간 전환 후 저장 내용 유지를 확인했습니다. 실제 사용자 프로젝트에 대한 쓰기나 AI 호출은 하지 않았습니다.

- 목록은 현재 사용하는 보기만 생성합니다. 항목 선택·체크박스 변경 시 목록을 다시 만들지 않으며, 검색용 문자열과 숫자 정렬 비교기를 재사용합니다. 한글 조합 중에는 검색 갱신을 미룹니다.
- PDF·Excel·Word·압축 문서 도구는 해당 파일을 읽거나 내보낼 때 처음 불러옵니다. 로딩 실패 시 새로고침 없이 재시도할 수 있습니다.
- 문서함 로딩 상태 표시, 고유번호 계층 필터 개수 표시, 모바일 전체 표 전환과 상세 저장 버튼의 화면 높이를 보완했습니다.

6.5.1 검증: 동일 브라우저의 가상 요구사항 600개로 각 동작 5회 측정한 중앙값은 목록 갱신 190.5→96.4ms, 검색 갱신 208.7→95.9ms, 상세 전환 처리 37.7→1.8ms였습니다. 기본 보기의 DOM 요소는 33,250→7,450개로 줄었습니다. 로컬 화면 처리 측정이며 AI·Drive 응답 시간은 포함하지 않습니다. 자동 검사 98개 통과 및 다중 시트 Excel 읽기·질의사항 내보내기를 확인했습니다.

- AI 연결에서 Gemini·GPT·Claude 선택. Claude는 Sonnet 5.5·Haiku 5.5·Opus 5.5를 지원하며, 쉽게 풀어보기·용어 도우미·사업정보 분석에 같은 연결을 사용합니다. Claude 실호출은 사용자의 API 키로 확인이 필요합니다.

- 황금 마슈라비야: 짙은 녹색, 금빛 기하학 문양, 아이보리 읽기 영역. 선택한 02번 남성 픽토그램 로고 적용. 상단은 로고·메뉴, 검색·작업 버튼, 분류의 3줄 구성. 고유번호 계층은 필터에서, 문서·검토 현황은 메뉴의 팝업에서 열람.
- 문서함·프로젝트·공유·비밀번호·AI 연결·사업 정보·안내창에도 동일한 색채 적용.
- 기존 상세 설명은 내부 스크롤 없는 읽기 전용 영역. 화면 표시에서만 연속 문장을 연결하며 저장된 원문은 유지. 새 요구사항 추가 시에는 입력 가능.
- 전체 표 보기, 접을 수 있는 상세 보조 항목, 작성 중 표시와 항목 이동 시 미저장 변경 확인. 저장 후 편집 위치와 펼친 항목 유지.
- 프로젝트·공유·비밀번호·문서함·AI 연결·사업 정보·안내창에 공통 디자인과 키보드 이동 적용. 모바일에서는 목록과 편집을 전환.
- 관련·상충 요구사항 기능 제거, 담당자 입력 숨김, 상세 설명 높이 확대.
- RFP·자료 관리: 원본 보관, 다운로드, 기본 RFP 지정·요구사항 추출. 프로젝트 설정에서 공유와 비밀번호 변경.
- 재분석 시 기존 편집 내용을 보존하고 새 원문을 별도로 기록.
- AI 연결: 별도 도우미 없이 브라우저 설정 유지. 연결 해제 버튼 제공.
- 쉬운 설명과 용어 사전 모두 동일한 AI 연결 사용. 요청할 때만 실행.
- 용어 뜻이 불명확하면 후보 최대 3개 제공.
- ‘사업 정보’: RFP별 사업개요·기간·일정·예산·제출·평가·계약 등을 요청형 AI 분석으로 정리하고 원문 근거와 함께 저장.
- 샘플 데이터 버튼, 데이터셋, 샘플 불러오기 기능 제거.

## 사업 정보 정리

1. ‘RFP·자료 관리’에 원본 RFP를 추가합니다. 요구사항이 없는 문서도 원본 보관 후 사업 정보를 분석할 수 있습니다.
2. 상단 ‘사업 정보’에서 RFP를 선택하고 ‘문서 읽기’를 누릅니다.
3. 읽은 분량과 AI 요청 횟수를 확인하고 ‘AI 분석 시작’을 누릅니다. 미연결 상태라면 먼저 표시되는 ‘AI 연결하기’에서 설정합니다.
4. 분류별 내용과 원문 근거를 검토하고 ‘결과 저장’을 누릅니다. 공유 프로젝트에서는 같은 URL로 접속한 사람도 저장 결과를 볼 수 있습니다.

화면 위쪽에 문서 선택 → 문서 읽기 → AI 분석 → 검토·저장의 현재 단계를 표시합니다. PDF 읽기는 읽은 페이지 수, AI 분석은 완료한 구간 수로 진행률을 계산합니다. 원본 불러오기·저장 처리처럼 비율을 계산할 수 없는 구간은 처리 중으로 표시합니다. 분석 100%와 저장 완료는 별도 상태입니다. 중단·실패 시 완료한 분석 구간을 유지하고, 저장 실패는 AI 재호출 없이 저장만 재시도합니다. 요구사항 추출·분류는 브라우저 규칙 기반이며 AI API를 호출하지 않습니다.

긴 문서는 모든 텍스트 구간을 나눠 읽습니다. 중단·실패 후 같은 창에서 다시 분석하면 완료된 구간은 재호출하지 않습니다. 원문 인용이 확인되지 않은 결과는 제외하며, ‘확인되지 않음’은 문서에 해당 정보가 없다는 뜻이 아닙니다. 스캔 문서는 OCR 처리된 PDF가 필요합니다. 실제 API 응답 품질은 연결된 계정과 업무용 RFP로 추가 검토가 필요합니다.

## 프로젝트 공동 작업

Google Drive 저장소와 GitHub Pages를 함께 사용합니다. 프로젝트 URL과 비밀번호로 접속하며, 전체 목록 열람에는 별도의 목록 관리자 인증이 필요합니다.

- 프로젝트별 URL과 관리자·사용자 비밀번호.
- 프로젝트 생성 시 관리자용·사용자용 비밀번호를 각각 두 번 입력하고 일치 여부 확인. 접속·생성·변경 화면의 비밀번호 보기/숨기기 지원.
- 관리자만 파일 삭제·비밀번호 변경.
- 항목별 수정 버전 검사와 마지막 저장 일시.
- 마지막 RFP 삭제 방지, 원본 파일과 작성한 내용 분리.

검토 중인 `127.0.0.1` 주소는 다른 PC에 공유하는 주소가 아닙니다. 공개 배포 시 Apps Script의 `APP_ORIGIN`을 `https://sjk3446.github.io`로 맞춘 뒤 GitHub Pages에서 연결을 다시 검증해야 합니다. 기존 브라우저 프로젝트는 자동으로 공유 프로젝트로 옮겨지지 않습니다.

[Google Drive 연결 설정](cloud/설정안내.md)을 참고하세요.

## AI 연결

### 프로젝트 자연어 질문

검색창에 질문을 입력하고 `AI 질문`을 누릅니다. 기본 RFP 원문·관련자료·등록된 요구사항에서 관련 구간만 브라우저에서 검색한 뒤 AI 답변을 1회 요청합니다. 전체 문서를 매번 보내지 않으며 기본 근거 분량은 6,000자·8구간 이내입니다. 같은 질문과 같은 원문이면 현재 탭에서 답변을 재사용합니다. 원문 내용이 바뀌면 다시 생성합니다. 검색어 확장 AI는 `AI로 검색어를 넓혀 다시 찾기`를 명시적으로 눌렀을 때만 호출되며 이때 근거 범위를 최대 12,000자·12구간으로 늘립니다.

답변에는 검증한 원문 인용·파일명·페이지 또는 시트·해당 요구사항 이동을 제공합니다. 근거가 없거나 자료가 일부 누락된 경우 확정하지 않으며 상충 조건은 양쪽 근거를 표시하도록 요청합니다. 기존 사업정보 AI 요약을 필수로 요구하지 않습니다. 원문 읽기와 검색 준비에는 AI를 호출하지 않습니다. 자동 작성된 답변은 실제 원문을 함께 검토하세요.

공유 링크·비밀번호 변경·새 공유 프로젝트 생성은 상단 `프로젝트`에서 관리합니다. `문서함`은 RFP·관련자료의 추가·분석·다운로드·삭제만 제공합니다.

### 비정형 RFP의 요구사항 추출

`문서함 → 각 RFP의 AI 요구사항 추출` 또는 `목록 도구 → AI 요구사항 추출`을 엽니다. 문서 읽기로 분량을 확인하고, 연결된 API로 AI 분석을 실행합니다. 완료 후 원문 위치·상세 근거를 검토하고 체크한 후보만 목록에 추가합니다. 원문에 없는 요구사항 ID는 만들지 않으며 별도의 내부 식별자로 관리합니다. ID가 없더라도 상태·플래그·질의사항을 저장할 수 있습니다. 기존 ID 또는 같은 파일의 동일 후보는 중복 추가를 막으며, 기존 작성 내용은 덮어쓰지 않습니다. 문서 버전 간 의미가 같은 항목을 자동 연결하는 기능은 포함하지 않습니다.

AI는 후보를 정리하며 원문 근거가 확인되지 않은 후보는 제외합니다. 빠진 항목이 없는지는 원문과 함께 검토하세요. 원본을 읽을 수 없는 스캔 문서에는 먼저 OCR이 필요합니다. 기존 `규칙 기반 추출`은 AI를 호출하지 않습니다.

1. `AI 연결`을 누릅니다.
2. Gemini, GPT 또는 Claude와 모델을 선택합니다.
3. 본인의 API 키를 입력하고 `키 등록하고 사용`을 누릅니다. 서비스당 키를 하나씩 등록할 수 있습니다.
4. 설정은 같은 브라우저에서 다시 열어도 유지됩니다.
5. 다른 AI로 전환하려면 해당 서비스를 선택하고 `이 AI 사용 / 적용`을 누릅니다. 키 입력란을 비워 두면 그 서비스에 저장된 키를 사용합니다. 다른 서비스의 키는 유지됩니다.
6. `연결 해제`는 사용만 중단하며 등록된 키는 유지합니다. 키 자체를 지우려면 해당 서비스를 선택하고 `선택 서비스 키 삭제`를 누릅니다.

## 프로젝트 질문과 히스토리

검색창의 `AI 질문`은 프로젝트의 기본 RFP·관련자료·요구사항에서 관련 원문을 브라우저에서 먼저 검색하고, 필요한 발췌만 이용해 답변합니다. 일반 검색은 기존대로 AI를 사용하지 않습니다. 새 질문은 기본 1회 답변 요청이며, 같은 자료·질문의 저장 답변은 API 호출 없이 재사용합니다. `AI로 검색어를 넓혀 다시 찾기`만 추가 검색어 요청과 더 넓은 근거를 사용합니다. 답변의 인용문은 제공한 원문과 대조하며, 근거가 부족하면 추가 확인 상태로 표시합니다. 검색에서 누락된 문서나 스캔 문서는 답변에도 누락될 수 있으니 중요한 판단은 원문을 확인하세요.

답변은 기본적으로 `나만 보기`로 저장됩니다. 이는 개인 계정이 아니라 **현재 브라우저** 기준입니다. 개인 답변은 프로젝트 문서·백업·공유 메타데이터에 포함하지 않습니다. 공유 프로젝트에서 히스토리의 체크박스로 답변을 선택하고 `프로젝트 공유`를 누르면 기존 URL과 프로젝트 비밀번호로 접속한 분들이 읽을 수 있습니다. `나만 보기`를 누르면 현재 브라우저에 사본을 남기고 프로젝트 공유 목록에서 제거합니다. 이미 다른 사람이 보관한 사본은 회수하지 않습니다. 새 질문은 질문한 사람의 API 설정을 사용하고, 저장 답변을 열람하거나 공개 범위를 바꾸는 작업은 AI를 호출하지 않습니다.

상단 `프로젝트`에는 공유 링크·비밀번호 변경·새 공유 프로젝트 기능을 모았습니다. `문서함`은 RFP·관련자료의 업로드·분석·다운로드·관리에 사용합니다. 브라우저 프로젝트에는 공유 권한이 없으며 별도의 공유 프로젝트를 생성해야 합니다. 기존 브라우저 프로젝트를 자동으로 공유 프로젝트로 복사하지 않습니다.

설정은 별도 암호화 저장소에 보관하며 프로젝트 백업에는 포함하지 않습니다. 기존 Python 도우미의 키는 처음 한 번 다시 입력해야 합니다. 브라우저 데이터 삭제나 기기 변경 시에는 다시 설정해야 합니다.

Gemini 무료 여부와 API 사용료는 제공사와 해당 API 계정 설정에 따릅니다. 한도 초과 시 다른 모델로 자동 전환하지 않습니다.

사업정보 분석은 원문을 최대 8,000자씩 나누고 응답 한도를 16,384토큰으로 설정합니다. 출력 한도·시간 초과·잘못된 JSON 응답은 실패한 구간만 더 작게 나누어 이어서 분석합니다. 자동 분할은 구간당 최대 3단계이며, 완료된 구간은 다시 요청하지 않습니다. API 키 오류·사용 한도·정책 차단은 자동 재시도하지 않고 사유를 표시합니다. 분석 구간 수는 분할에 따라 늘어날 수 있으며 진행률은 완료한 원문 분량을 기준으로 계산합니다. 분석을 완료한 뒤 `결과 저장`을 눌러 공유 프로젝트에 저장합니다.
