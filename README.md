## 사업 정보 정리

1. ‘RFP·자료 관리’에 원본 RFP를 추가합니다. 요구사항이 없는 문서도 원본 보관 후 사업 정보를 분석할 수 있습니다.
2. 상단 ‘사업 정보’에서 RFP를 선택하고 ‘문서 읽기’를 누릅니다.
3. 읽은 분량과 AI 요청 횟수를 확인하고 ‘AI 분석 시작’을 누릅니다. 미연결 상태라면 먼저 표시되는 ‘AI 연결하기’에서 설정합니다.
4. 분류별 내용과 원문 근거를 검토하고 ‘결과 저장’을 누릅니다. 공유 프로젝트에서는 같은 URL로 접속한 사람도 저장 결과를 볼 수 있습니다.

화면 위쪽에 문서 선택 → 문서 읽기 → AI 분석 → 검토·저장의 현재 단계를 표시합니다. PDF 읽기는 읽은 페이지 수, AI 분석은 완료한 구간 수로 진행률을 계산합니다. 원본 불러오기·저장 처리처럼 비율을 계산할 수 없는 구간은 처리 중으로 표시합니다. 분석 100%와 저장 완료는 별도 상태입니다. 중단·실패 시 완료한 분석 구간을 유지하고, 저장 실패는 AI 재호출 없이 저장만 재시도합니다. 요구사항 추출·분류는 브라우저 규칙 기반이며 AI API를 호출하지 않습니다.

긴 문서는 모든 텍스트 구간을 나눠 읽습니다. 중단·실패 후 같은 창에서 다시 분석하면 완료된 구간은 재호출하지 않습니다. 원문 인용이 확인되지 않은 결과는 제외하며, ‘확인되지 않음’은 문서에 해당 정보가 없다는 뜻이 아닙니다. 스캔 문서는 OCR 처리된 PDF가 필요합니다. 실제 API 응답 품질은 연결된 계정과 업무용 RFP로 추가 검토가 필요합니다.

## 프로젝트 공동 작업

Google Drive 저장소는 배포하였으며, 현재 PC의 공유 검토 화면에서 프로젝트 생성·사용자 접속·공동 저장과 동시 수정 충돌 차단을 확인했습니다. GitHub 공개 사이트는 아직 이전 버전입니다.

- 프로젝트별 URL과 관리자·사용자 비밀번호.
- 프로젝트 생성 시 관리자용·사용자용 비밀번호를 각각 두 번 입력하고 일치 여부 확인. 접속·생성·변경 화면의 비밀번호 보기/숨기기 지원.
- 관리자만 파일 삭제·비밀번호 변경.
- 항목별 수정 버전 검사와 마지막 저장 일시.
- 마지막 RFP 삭제 방지, 원본 파일과 작성한 내용 분리.

검토 중인 `127.0.0.1` 주소는 다른 PC에 공유하는 주소가 아닙니다. 공개 배포 시 Apps Script의 `APP_ORIGIN`을 `https://sjk3446.github.io`로 맞춘 뒤 GitHub Pages에서 연결을 다시 검증해야 합니다. 기존 브라우저 프로젝트는 자동으로 공유 프로젝트로 옮겨지지 않습니다.

[Google Drive 연결 설정](cloud/설정안내.md)을 참고하세요.

## AI 연결

### 프로젝트 자연어 질문

검색창에 질문을 입력하고 `AI 질문`을 누릅니다. 기본 RFP 원문·관련자료·등록된 요구사항에서 관련 구간만 브라우저에서 검색한 뒤 AI 답변을 1회 요청합니다. 전체 문서를 매번 보내지 않으며 기본 근거 분량은 6,000자·8구간 이내입니다. 같은 질문과 같은 원문이면 현재 탭에서 답변을 재사용합니다. 원문 내용이 바뀌면 다시 생성합니다. 검색어 확장 AI는 `AI로 검색어를 넓혀 다시 찾기`를 명시적으로 눌렀을 때만 호출되며 이때 근거 범위를 최대 12,000자·12구간으로 늘립니다.

답변에는 검증한 원문 인용·파일명·페이지 또는 시트·해당 요구사항 이동을 제공합니다. 근거가 없거나 자료가 일부 누락된 경우 확정하지 않으며 상충 조건은 양쪽 근거를 표시하도록 요청합니다. 기존 사업정보 AI 요약을 필수로 요구하지 않습니다. 원문 읽기와 검색 준비에는 AI를 호출하지 않습니다. 자동 작성된 답변은 실제 원문을 함께 검토하세요.

공유 링크·비밀번호 변경·새 공유 프로젝트 생성은 상단 `프로젝트`에서 관리합니다. `문서함`은 RFP·관련자료의 추가·분석·다운로드·삭제만 제공합니다.

### 비정형 RFP의 요구사항 추출

`문서함 → 각 RFP의 AI 요구사항 추출` 또는 `목록 도구 → AI 요구사항 추출`을 엽니다. 문서 읽기로 분량을 확인하고, 연결된 API로 AI 분석을 실행합니다. 완료 후 원문 위치·상세 근거를 검토하고 체크한 후보만 목록에 추가합니다. 원문에 없는 요구사항 ID는 만들지 않으며 별도의 내부 식별자로 관리합니다. ID가 없더라도 상태·플래그·질의사항을 저장할 수 있습니다. 기존 ID 또는 같은 파일의 동일 후보는 중복 추가를 막으며, 기존 작성 내용은 덮어쓰지 않습니다. 문서 버전 간 의미가 같은 항목을 자동 연결하는 기능은 포함하지 않습니다.

AI는 후보를 정리하며 원문 근거가 확인되지 않은 후보는 제외합니다. 빠진 항목이 없는지는 원문과 함께 검토하세요. 원본을 읽을 수 없는 스캔 문서에는 먼저 OCR이 필요합니다. 기존 `규칙 기반 추출`은 AI를 호출하지 않습니다.

1. `AI 연결`을 누릅니다.
2. Gemini, GPT 또는 Claude와 모델을 선택합니다.
3. 본인의 API 키를 입력하고 `키 등록하고 사용`을 누릅니다. 서비스당 키를 하나씩 등록할 수 있습니다.
4. 설정은 같은 브라우저에서 다시 열어도 유지됩니다.
5. 다른 AI로 전환하려면 해당 서비스를 선택하고 `이 AI 사용 / 적용`을 누릅니다. 키 입력란을 비워 두면 그 서비스에 저장된 키를 사용합니다. 다른 서비스의 키는 유지됩니다.
6. `연결 해제`는 사용만 중단하며 등록된 키는 유지합니다. 키 자체를 지우려면 해당 서비스를 선택하고 `선택 서비스 키 삭제`를 누릅니다.

## 프로젝트 질문과 히스토리

검색창의 `AI 질문`은 프로젝트의 기본 RFP·관련자료·요구사항에서 관련 원문을 브라우저에서 먼저 검색하고, 필요한 발췌만 이용해 답변합니다. 일반 검색은 기존대로 AI를 사용하지 않습니다. 새 질문은 기본 1회 답변 요청이며, 같은 자료·질문의 저장 답변은 API 호출 없이 재사용합니다. `AI로 검색어를 넓혀 다시 찾기`만 추가 검색어 요청과 더 넓은 근거를 사용합니다. 답변의 인용문은 제공한 원문과 대조하며, 근거가 부족하면 추가 확인 상태로 표시합니다. 검색에서 누락된 문서나 스캔 문서는 답변에도 누락될 수 있으니 중요한 판단은 원문을 확인하세요.

답변은 기본적으로 `나만 보기`로 저장됩니다. 이는 개인 계정이 아니라 **현재 브라우저** 기준입니다. 개인 답변은 프로젝트 문서·백업·공유 메타데이터에 포함하지 않습니다. 공유 프로젝트에서 히스토리의 체크박스로 답변을 선택하고 `프로젝트 공유`를 누르면 기존 URL과 프로젝트 비밀번호로 접속한 분들이 읽을 수 있습니다. `나만 보기`를 누르면 현재 브라우저에 사본을 남기고 프로젝트 공유 목록에서 제거합니다. 이미 다른 사람이 보관한 사본은 회수하지 않습니다. 새 질문은 질문한 사람의 API 설정을 사용하고, 저장 답변을 열람하거나 공개 범위를 바꾸는 작업은 AI를 호출하지 않습니다.

상단 `프로젝트`에는 공유 링크·비밀번호 변경·새 공유 프로젝트 기능을 모았습니다. `문서함`은 RFP·관련자료의 업로드·분석·다운로드·관리에 사용합니다. 브라우저 프로젝트에는 공유 권한이 없으며 별도의 공유 프로젝트를 생성해야 합니다. 기존 브라우저 프로젝트를 자동으로 공유 프로젝트로 복사하지 않습니다.

설정은 별도 암호화 저장소에 보관하며 프로젝트 백업에는 포함하지 않습니다. 기존 Python 도우미의 키는 처음 한 번 다시 입력해야 합니다. 브라우저 데이터 삭제나 기기 변경 시에는 다시 설정해야 합니다.

Gemini 무료 여부와 API 사용료는 제공사와 해당 API 계정 설정에 따릅니다. 한도 초과 시 다른 모델로 자동 전환하지 않습니다.

사업정보 분석은 원문을 최대 8,000자씩 나누고 응답 한도를 16,384토큰으로 설정합니다. 출력 한도·시간 초과·잘못된 JSON 응답은 실패한 구간만 더 작게 나누어 이어서 분석합니다. 자동 분할은 구간당 최대 3단계이며, 완료된 구간은 다시 요청하지 않습니다. API 키 오류·사용 한도·정책 차단은 자동 재시도하지 않고 사유를 표시합니다. 분석 구간 수는 분할에 따라 늘어날 수 있으며 진행률은 완료한 원문 분량을 기준으로 계산합니다. 분석을 완료한 뒤 `결과 저장`을 눌러 공유 프로젝트에 저장합니다.
