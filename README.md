# Reqly Pages

RFP 문서를 사용자의 브라우저에서 직접 읽고 요구사항을 관리하는 GitHub Pages 전용 웹 앱입니다.

## 이 버전의 중요한 원칙

- 로그인, 회원가입, 관리자 페이지, NAS, 중앙 데이터베이스가 없습니다.
- 업로드한 RFP와 작업 내용은 GitHub에 저장되지 않습니다.
- 문서는 브라우저 안에서 분석하며, 결과는 해당 브라우저의 IndexedDB에만 저장합니다.
- 브라우저 데이터 삭제, 시크릿 모드 종료, 기기 교체 시 자료가 없어질 수 있으므로 `프로젝트 → 백업`을 이용해야 합니다.
- 한 브라우저에 프로젝트를 최대 3개 저장할 수 있습니다.
- AI 기능은 선택 사항입니다. AI 연결이 없어도 업로드, 추출, 편집, 필터, 플래그, 일괄 변경, 관계 비교, 내보내기를 사용할 수 있습니다.

## 지원 기능

- RFP 원문의 요구사항 ID를 그대로 보존하며, ID가 없는 항목에는 번호를 만들지 않습니다.
- 형식이 다른 RFP의 표·목록·서술형 요구 문장을 함께 찾습니다.
- Excel의 모든 시트를 검사하고 요구사항 표가 있는 여러 시트를 합칩니다.
- PDF, DOCX, PPTX, HWPX, XLSX/XLSM/XLS, CSV/TSV, TXT/MD/JSON/XML을 브라우저에서 분석합니다.
- 회의록, 녹취록 문서, 참고자료를 프로젝트에 추가할 수 있습니다.
- 요구사항 ID 계층 필터, RFP 원문 순서 정렬, 검색, 상태·우선순위·5색 플래그 필터를 제공합니다.
- 체크박스로 여러 요구사항의 상태·우선순위·플래그를 일괄 변경할 수 있습니다.
- 관련·상충 요구사항을 나란히 비교하고 핵심 공통·상충 구절을 강조합니다.
- 질의 직접 입력, UI/UX·개발 관점 질의 제안, 질의응답 Excel 내보내기를 지원합니다.
- 쉬운 설명과 용어 도우미는 사용자가 눌렀을 때만 실행합니다.
- 수동 용어 등록을 우선하며, 문맥상 뜻이 여러 개면 최대 3개 후보를 표시합니다.

## PC에서 미리 확인하기

정적 파일도 보안상 브라우저 주소를 통해 여는 것이 좋습니다. 이 폴더에서 PowerShell을 열고 다음을 실행합니다.

```powershell
python -m http.server 8765
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. 종료할 때는 PowerShell 창에서 `Ctrl+C`를 누릅니다.

## AI 로컬 보안 도우미

AI를 쓰지 않으면 이 절차는 생략해도 됩니다.

‘쉽게 풀어보면’은 실제 AI 연결이 있어야 생성됩니다. 연결되지 않은 상태에서 원문을 재배열한 결과를 대신 보여주지 않습니다. AI는 뜻, 해야 할 일, 쉬운 예시, 완료 확인 방법, 추가 확인 사항으로 해설하며 사용자가 요청할 때만 호출합니다. 저장된 설명 열람에는 AI를 다시 호출하지 않습니다. 실패하거나 응답이 잘린 경우 기존 설명을 유지합니다.

기존 도우미를 사용 중이라면 최신 ZIP을 다시 받아 압축을 풀고, 기존 도우미를 종료한 뒤 새 도우미를 실행하세요. 웹 화면에서 새 6자리 코드로 다시 연결하면 됩니다. 기존 암호화 API 키 파일은 유지됩니다.

1. 웹 화면의 `AI 연결 → AI 도우미 다운로드`를 누르고 ZIP 압축을 풉니다. 저장소 폴더를 이미 가지고 있다면 `local-helper` 폴더를 바로 사용해도 됩니다.
2. 압축을 푼 폴더의 `Reqly-AI-도우미.bat`를 더블클릭합니다.
3. 검은 창에 표시되는 6자리 연결 번호를 확인합니다.
4. Reqly 화면 위쪽의 `AI 연결`을 누릅니다.
5. 6자리 번호를 입력하고 `연결`을 누릅니다.
6. 본인의 OpenAI API 키를 입력하고 `Windows 암호화 저장`을 누릅니다.
7. 도우미 창은 AI를 사용하는 동안 열어 둡니다.

저장 흐름은 다음과 같습니다.

```text
브라우저에서 API 키 입력
  → 내 PC의 127.0.0.1:8766 로컬 Python 도우미로 전달
  → Windows DPAPI가 현재 Windows 사용자 계정에 묶어 암호화
  → %LOCALAPPDATA%\Reqly\api-key.dpapi 에 암호문만 저장
```

브라우저에는 API 키를 저장하지 않습니다. 도우미는 실행할 때마다 새 6자리 연결 번호를 만들며, 연결 권한은 브라우저 탭을 닫거나 도우미를 종료하면 사라집니다. AI 요청 시에는 현재 요청한 요구사항과 직접 관련된 참고 문맥만 AI 제공사로 전송됩니다. 요청은 단발성으로 보내며 API의 응답 저장 옵션도 끈 상태(`store: false`)입니다. 다만 AI 제공사의 보안·오남용 방지 보존 정책까지 없애는 기능은 아닙니다.

Python이 없다면 [Python Windows 설치 페이지](https://www.python.org/downloads/windows/)에서 Python 3을 설치하면서 `Add Python to PATH`를 선택하세요. 추가 패키지는 필요 없습니다.

## GitHub Pages에 게시하기

아직 이 저장소는 자동으로 GitHub에 올라가지 않습니다. 게시할 준비가 된 뒤 아래 순서로 진행합니다.

1. GitHub에서 새 저장소를 만듭니다.
2. 이 폴더의 파일을 그 저장소에 올립니다.
3. GitHub 저장소의 `Settings → Pages`를 엽니다.
4. `Build and deployment`에서 `Deploy from a branch`를 선택합니다.
5. 브랜치는 `main`, 폴더는 `/(root)`를 선택하고 저장합니다.
6. 잠시 뒤 표시되는 `https://계정명.github.io/저장소명/` 주소로 접속합니다.

`index.html`이 상대경로를 사용하므로 사용자 사이트와 프로젝트 사이트 양쪽에서 작동합니다.

## 사용자가 반드시 알아야 하는 제한

- 서로 다른 PC나 브라우저의 프로젝트는 자동으로 공유되지 않습니다.
- 같은 URL을 사용해도 각 사용자의 데이터는 서로 보이지 않습니다.
- 저장 공간은 브라우저 정책과 기기 여유 공간에 따라 달라집니다.
- 구형 `.hwp`는 브라우저에서 안정적으로 해석할 수 없으므로 `.hwpx`, PDF 또는 DOCX로 저장한 뒤 올려야 합니다.
- 문서 분석용 라이브러리는 jsDelivr CDN에서 불러오므로 첫 접속과 새로고침에는 인터넷 연결이 필요합니다. 파일 내용은 CDN으로 보내지 않습니다.
- GitHub Pages는 HTTPS이며 최신 Chrome/Edge는 로컬 도우미 연결 시 `로컬 네트워크 접근` 허용 창을 표시할 수 있습니다. 이때 허용해야 AI 기능을 쓸 수 있습니다.
