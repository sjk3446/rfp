# Google Drive 연결 준비

현재는 로컬 검토 버전입니다. Google 웹 앱 배포와 검토 화면의 연결 응답을 확인했습니다. 프로젝트 생성 이후 실제 저장과 두 브라우저 공동편집 검증은 아직 남아 있습니다. 기존 브라우저 프로젝트는 그대로 남아 있습니다.

검토 화면의 `RFP·자료 관리 → 새 공유 프로젝트`로 접속할 수 있습니다. `mode=local` 주소는 기존 브라우저 프로젝트를 여는 데 사용합니다. 외부에서 접속할 앱 주소는 GitHub 게시 후 별도로 검증합니다.

## 전하의 계정에서 한 번 필요한 설정

1. `https://script.google.com`에서 새 프로젝트를 만들고 이름을 `Reqly Drive`로 지정합니다.
2. 기본 `Code.gs`에 이 폴더의 `Code.gs` 내용을 넣습니다.
3. HTML 파일을 추가하고 이름을 `Bridge`로 지정한 뒤 `Bridge.html` 내용을 넣습니다.
4. 프로젝트 설정에서 `appsscript.json` 표시를 켜고 이 폴더의 설정 내용을 넣습니다.
5. 편집기에서 `initializeStorage` 함수를 한 번 실행합니다. Google의 권한 승인 화면은 계정 소유자가 직접 확인합니다.
6. 프로젝트 설정의 스크립트 속성에 `ROOT_FOLDER_ID`, `SERVER_SECRET`, `APP_ORIGIN`이 만들어졌는지 확인합니다. 비밀값을 채팅에 붙여 넣지 마세요.
7. `APP_ORIGIN`의 운영 값은 `https://sjk3446.github.io`입니다. 로컬 연결 검증 시에만 `http://127.0.0.1:8876`으로 바꾸고, 검증 뒤 운영 값으로 돌립니다.
8. 배포 → 새 배포 → 웹 앱을 선택합니다. 실행 사용자는 소유자, 접근 범위는 모든 사용자로 설정합니다. 이 권한 설정은 소유자가 직접 승인해야 합니다.
9. `/exec`로 끝나는 배포 주소를 `cloud-config.js`의 `endpoint`에 넣습니다. 주소에는 비밀번호를 넣지 않습니다.

Drive에는 `Reqly projects`라는 전용 폴더가 만들어집니다. 폴더 공유 권한은 바꾸지 않습니다. 앱을 통한 접근 권한은 프로젝트별로 확인합니다.

## 반드시 확인할 사항

- 새 프로젝트와 관리자용·사용자용 비밀번호 설정.
- 프로젝트 URL을 다른 브라우저에서 열고 사용자 비밀번호로 접속.
- 사용자에게 파일 삭제·비밀번호 변경 버튼이 없으며 직접 요청도 거절되는지 확인.
- 같은 항목을 두 브라우저에서 열고 차례로 저장할 때 두 번째 저장이 거절되는지 확인.
- 서로 다른 항목 저장은 모두 유지되는지 확인.
- 마지막 저장 정보가 약 10초 간격으로 갱신되는지 확인.
- 입력 중인 내용은 새 저장 상태 확인 때문에 바뀌지 않는지 확인.
- 원본 PDF 다운로드와 원문 보기. 특히 실제 RFP 크기의 업로드·다운로드를 확인.
- 마지막 RFP와 현재 선택한 RFP를 삭제하지 못하는지 확인.
- 관리자 비밀번호 또는 사용자 비밀번호 변경 후 해당 권한의 기존 접속이 무효화되는지 확인.
- 기존 프로젝트 백업의 이전은 별도 확인 후 진행. 자동 이전하지 않습니다.

## 현재 한계

- 실제 Google 계정 배포·권한 승인과 브라우저 간 통신은 아직 검증 전입니다.
- 파일 최대 30MB는 기존 앱 기준입니다. Apps Script의 브라우저 통신으로 이 크기가 안정적으로 처리되는지는 실제 배포에서 확인해야 합니다.
- ID가 없거나 중복되어 새 RFP와 대응이 불명확하면 재분석 반영을 중단합니다. 수동 대응 화면은 아직 준비 중입니다.
- PDF 전체보기는 원본 뷰어를 사용합니다. 비PDF 문서의 정교한 원문 뷰어·자동 목차는 후속 작업입니다.
- 공용 비밀번호 방식이므로 개인별 수정자를 식별하지 않습니다.
- 추측 시도를 줄이는 접속 제한은 프로젝트 단위입니다. 많은 사람이 쓰는 공개 서비스로 확장할 때는 별도의 남용 방지 설계가 필요합니다.
- 프로젝트별 파일은 Drive 휴지통으로 이동하므로 소유자가 복원할 수 있습니다. 파일 목록 복구 화면은 아직 없습니다.

## AI 설정

AI 연결은 별도 프로그램 없이 API 키를 한 번 입력하는 방식입니다. 같은 브라우저의 탭 종료·재시작 이후에도 유지됩니다. 명시적인 연결 해제, 브라우저 데이터 삭제, API 키 폐기, 제공사 오류·한도 도달은 구분합니다.

설정 저장은 암호화되어 있으나 현재 브라우저 프로필에서 사용하는 방식이며, 이전 Windows 계정 DPAPI 방식과 동일한 보호 방식은 아닙니다. 실제 API 키를 사용한 응답 품질은 별도 확인이 필요합니다.
